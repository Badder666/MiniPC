# 反馈失效导致下发力矩为零

## 实测定位

2026-10-10 订阅USB转换后的ROS状态20秒，共1967帧。1711帧掩码63、228帧掩码3、28帧掩码11。

掩码从63变成3时，J1/J2有效，J3～J6无效。板端对电机反馈使用250 ms新鲜度检查。J3～J6位置同时停止更新，无效区持续约2.551秒；随后J4先恢复，再恢复全部六轴。

发生转换时J2/J3编码值约1.300/1.226 rad。按报文保留的位置计算，J3模型重力力矩约1.318 N·m，但失效轴输出掩码不含J3，因此上位机力矩数组为0，板端也清零该轴接收力矩。不能把这个0解释为质心模型在某个角度天然变号或零点。

## 已修复的连带误算

原上位机 `pinocchio_gravity.py` 在反馈位无效时把模型关节角置为0，连带改变其余有效关节的重力计算。实测掩码63→3转换时，原J2指令从-0.768跳至-0.473 N·m；用最近报文保留的完整姿态计算应为-0.761 N·m。

已修改：所有关节的角度用当前报文保留的有限位置值做scale/offset转换，反馈有效掩码只控制对应电机是否输出。无效轴仍不输出力矩，不把过期轴伪装成有效。非有限姿态直接拒绝计算。保留的位置只能作为短期姿态参考，失效轴实际移动时，该姿态和其余轴重力计算仍可能不准，不能代替反馈链路修复。

`receiver_node.py` 新增掩码变化日志，明确列出失效轴和输出清零原因，全部恢复时记录恢复信息。

编译、3个回归测试通过；回放全部1967帧，所有有效轴与同报文完整有限姿态重力一致，无效轴输出保持0，移除的有效轴误算最大约0.994 N·m。已重启Pinocchio和RViz，保留新候选模型及比例1.0。

## 仍待排查

重启后400帧检查仍看到掩码3/11/31/63变化，说明反馈失效仍在发生。该软件修复没有解决CAN反馈中断。

优先检查J2后通往J3～J6的共同CAN及供电连接、接插件和活动线缆；也应检查CAN收发错误/队列情况。只有共同失效的观察，没有确定是哪根线或哪个硬件损坏。不要仅通过增大250 ms期限隐藏长时间反馈失效。

板端当前源码的CAN发送helper忽略 `HAL_FDCAN_AddMessageToTxFifoQ` 返回值，尚不能从现有日志确认发送队列是否丢帧。本次未修改、编译或烧录板端固件。
