# 上位机重力补偿编译与启动

以下命令在 Ubuntu 虚拟机终端执行。
工作目录为 `/home/badder/minipc/New_Custom_Controller`，模型为 URDF2。
板端本地补偿模型已移除，补偿力矩由上位机 Pinocchio 计算并通过 USB 回传。

## 修改补偿比例

在启动命令中设置 `torque_scale:=1.0`，表示使用 Pinocchio 计算力矩的 100%。
例如 `torque_scale:=0.7` 为 70%，`torque_scale:=0.0` 为零补偿。
该比例应用于六轴力矩。当前节点只在启动时读取比例，修改比例须停止后重新启动；
仅改变启动参数不需要重新编译或烧录达妙板。

## 停止当前后台程序

本次由 SSH 启动的进程号保存在 `/tmp/controller_urdf2.pid`：

```bash
kill -INT "$(cat /tmp/controller_urdf2.pid)"
```

确认旧程序退出并释放串口，再启动新程序。若是在终端前台启动，使用 `Ctrl+C` 停止。
前台启动的进程不会更新上述后台 PID 文件，后续应使用该终端的 `Ctrl+C`。

## 编译

修改 Python 源码、配置或模型后，可执行：

```bash
cd ~/minipc/New_Custom_Controller
source /opt/ros/humble/setup.bash
colcon build --packages-select custom_controller_usb --symlink-install
source install/setup.bash
```

## 启动力矩回传和 RViz

在虚拟机桌面终端执行，USB 须连接到虚拟机的 `/dev/ttyACM0`：

```bash
cd ~/minipc/New_Custom_Controller
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch custom_controller_usb visualization.launch.py \
  protocol:=justfloat port:=/dev/ttyACM0 forward:=false \
  gravity_feedforward:=true gravity_dry_run:=false torque_scale:=1.0 \
  show_planned_trajectory:=false \
  trajectory_output_csv:=/tmp/controller_urdf2_live.csv
```

`gravity_dry_run:=false` 启用真实力矩回传；设为 `true` 时只计算。
新终端也要执行两条 `source` 命令。

## 方向、位置映射和运行检查

公用配置文件为 `src/custom_controller_usb/config/controller_mapping_urdf2.yaml`。
当前 `torque_signs` 为 `[1, -1, 1, -1, 1, 1]`，J2 已按实机反馈反转力矩。
位置映射 `position_scales` 为 `[-1, -1, 1, -1, 1, -1]`。
改力矩方向用 `torque_signs`，改编码器到模型的角度比例用 `position_scales`，
并同步 RViz 使用的 `scales`。零点偏置统一修改同一 YAML 中的 `offsets`，
RViz、绿色零点参考姿态和 Pinocchio 共用该值；修改后重启生效。
详细步骤见 `RViz关节零点校准.md`。

查询实际加载的参数：

```bash
ros2 param get /custom_controller/usb_receiver torque_scale
ros2 param get /custom_controller/usb_receiver torque_signs
ros2 param get /custom_controller/usb_receiver gravity_dry_run
```

本次后台程序日志为 `/tmp/controller_urdf2.log`，可用 `tail -f` 查看。
前台启动时日志直接显示在启动终端。
